# English UI and language catalogue

German remains the default. Select **English** on the landing page or in the settings footer, or open the game with `?lang=en`. `?lang=de` explicitly selects German. The preference is stored separately as `kepler7-ui-language`; it is not part of a saved colony.

## Delivered scope

The catalogue covers landing/authentication text, navigation and settings, resource/building/research/ship names, descriptions and common actions/errors. Count entries in `locales/en.json` rather than inferring translation completeness from file size.

Some dynamically assembled sentences, server-origin messages and secondary HTML pages still need localization. Historical patchnotes remain unchanged. Player chat, commander names and player-owned names must never be translated.

## Safety and implementation

- No third-party translation request or new runtime dependency. The catalogue is served by the game's own origin.
- The initial static DOM is translated before authentication and user data are loaded. Existing dynamic presentation hooks and the scoped observer retain their exclusions for player content.
- Dynamic UI output is localized at selected display sites. A WeakSet registers original static definition objects; presentation-only Proxy views translate their display properties without changing the underlying definition, ID or save. Unregistered player objects are returned unchanged. Frozen non-writable properties retain their original values to respect Proxy invariants.
- HTML translations are escaped. Selectors, event handlers, technical keys, comparison operands, tagged templates and historical `PATCHNOTES` literals are excluded by the compiler.
- The language selector uses the existing `sicherSpeichern()` helper before navigating from a loaded game. No new save or network protocol is introduced.
- There is still one game HTML file. The runtime is embedded; `kepler-english.json` is a separate generated asset fetched only in English mode. German starts without fetching or parsing that catalogue.
- The catalogue URL includes a hash of its generated bytes. A valid cached version is reused without a background download. Invalid cached HTML/JSON is discarded; failed downloads fall back to German with a visible retry notice and retain the saved English preference.
- The English bootstrap awaits the catalogue before starting authentication/game initialization. Service-worker registration handles both a future load event and a load event that already finished during that wait.
- The backend deployment copies the optional catalogue by its exact filename and generates its gzip companion. Deploy this backend support before publishing a frontend that references the asset.

## Development files

`locales/en.json` is the human-readable German-to-English catalogue. `tools/i18n/runtime.js` is its runtime template. `tools/i18n/catalog.cjs` owns canonical asset serialization, content-hash URLs and runtime rendering. `tools/i18n/build.cjs` uses development-only Acorn/Acorn Walk to find display sites in the original single-file application. `tools/i18n/test.cjs` tests transformation and runtime invariants. Browser tests exercise isolated HTTP origins in Chromium, not live player accounts.

For the current localized game, update `locales/en.json` and run `node tools/i18n/sync.cjs`. Commit the generated HTML and `kepler-english.json` together. `tools/ideas/sync.cjs` also preserves this external-catalogue format when refreshing idea translations. The original compiler retains an inline mode for isolated transformation fixtures.

Worker registration and cache readiness tests poll the actual Boolean result of `await page.evaluate(...)`. Do not treat a fulfilled `waitForFunction(async ...)` handle as proof that its resolved result was true: the installed Playwright polling implementation initially considers the returned Promise truthy. The load-only registration counterexample must fail with no actual registration/controller after the held language response is released.

### Initial reproducible build

This initial preview was compiled from game blob `db881c88728b38dd4ddc005f17caa12dc8eefe0d` (SHA-256 `d2e1a3525a0b657b36022725fc2c7175f90a94281575a52cbda419040bafb24e`). The compiler refuses to stack transformations onto already localized source.

In an isolated working copy containing that original game file:

```sh
npm install --prefix tools/i18n --ignore-scripts
node tools/i18n/build.cjs --check
node --test tools/i18n/test.cjs
node tools/i18n/build.cjs
node tests/run.js --nur-pflicht
node tests/test_english_locale.js
```

The browser test uses the repository's usual Playwright setup and `KEPLER_CHROMIUM` override. `K7_SCREENSHOT_DIR` optionally saves screenshots. `KEPLER_SPIELDATEI` points the test at a counterexample without replacing the working game file. The original German source must fail the English-feature test.

Do **not** restore this old game blob over a newer shared branch to add translations. Further work must reconcile newer game changes and keep the runtime, catalogue and display-site edits together. The present compiler is an initial migration tool, not an automatic production build step.

Targeted localization checks do not replace that full release gate. Verify the live catalogue bytes alongside the game HTML, service worker and release metadata.
